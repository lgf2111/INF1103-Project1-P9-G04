Overview

One assessment path, two interfaces

  • AI first, always. Every message goes through the AI Manager; nothing is scored from a cached guess.
  • Rules decide the band. Eight ordered rules turn validated findings and your exposure answers into a 0–100 score.
  • The verdict explains itself. Each result names the matched rule and traces every rule it checked.
  • Reports persist. JSON or SQLite behind one contract, queryable and exportable.

Telegram · Gmail monitor

Unread mail is checked every minute

  • /linkgmail stores the mailbox with an app password (file mode 0600).
  • /checkmail runs the same check immediately.
  • Only mail at MEDIUM or HIGH produces an alert; LOW mail is summarised once.
  • /unlinkgmail deletes the credential.

Design

Four managers, two abstract contracts

  • SRP: validator, storage, renderer, presenter each own one job.
  • OCP: a new rule or store is a subclass.
  • LSP: the storage suite passes on both backends.
  • DIP: managers depend on contracts.

DevOps

Green before it ships

  • CI runs lint, the offline suite, and the suite inside the Docker image.
  • Every change lands through a branch and a pull request.

11 / 13
Run it

Four commands

  • bash run.sh cli builds and runs the terminal interface.
  • bash run.sh gui runs the Telegram bot.
  • bash run.sh all runs both in one process, sharing one locked store.
  • bash run.sh test runs the suite inside the container.

The report data lives in .phishreport-data, mounted at /data in the container.

Limits and next

What it does not claim

  • A LOW result never means safe; the score ranks response urgency, not maliciousness.
  • Without exposure answers a chat assessment is capped at MEDIUM by design.
  • Gmail polling stores an app password (mode 0600); unlinking deletes it.
  • Exposure answers are stored for CLI and chat assessments alike, and the summary counts them.
