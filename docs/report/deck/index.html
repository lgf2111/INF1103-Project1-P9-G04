What it does

One assessment path, two interfaces

  • AI first, always. Every message goes through the AI Manager; nothing is scored from a cached guess.
  • Rules decide the band. Eight ordered rules turn validated findings and your exposure answers into a 0–100 score.
  • The verdict explains itself. Each result names the rule that matched and the fields it used.
  • Reports persist. JSON or SQLite, same contract, queryable and summarisable.

Design

Four managers, two abstract contracts

  • SRP — validator, storage, renderer and presenter each change for one reason.
  • OCP — a new rule is a PriorityRule subclass; a new store is a ReportStorage implementation.
  • LSP — the storage suite passes on both backends.
  • DIP — managers depend on contracts; wiring happens at the edges.
7 / 10
DevOps

Green before it ships

  • Lint, offline suite and a Docker job that runs the suite inside the Telegram image.
  • Every change lands through a branch, a pull request and a green check.
  • Tests never touch the live API; provider behaviour is stubbed.

Limits and next

What it does not claim

  • A LOW result never means "safe" — the score ranks response urgency, not maliciousness.
  • Without exposure answers, a chat assessment is capped at MEDIUM by design.
  • Gmail polling stores an app password (mode 0600) because polling needs it; unlinking deletes it.
  • Exposure answers are stored for CLI and chat assessments alike, and the summary counts them.
