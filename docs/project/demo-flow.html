PhishReport — 3-Minute Demo Flow

Phishing & exposure assessment CLI: paste a message, the AI interprets it, our rules give a priority, score and action checklist; reports saved locally.

Total: 3:00  •  2 presenters × 1 min + 1 min buffer  •  move fast, one action each

Before you start (10-second setup)

  • App already run once so reports.json has a saved report (for the quick "view" glance).
  • .env has a working GROQ_API_KEY; internet on; terminal font large.
  • Phishing message copied to clipboard; a known-good .eml in the saved folder.
  • App launched to the menu before the clock starts.
0:00–1:00

Part 1 — Core assessment (the main flow)

Presenter 1
Say"PhishReport checks suspicious messages. You paste the content, the AI interprets it, and our rules return a priority, a score, and an action checklist. Here's the core flow."
DemoChoose 1, paste an obvious phishing message, answer the quick follow-ups.
ActionPoint to the result: priority (HIGH), score, reasons, checklist — and note it's saved locally.
NoteUse a clearly-phishing message so it lands on HIGH. One clean run — don't retype.
1:00–2:00

Part 2 — Email import & robustness

Presenter 2
Say"Real emails come as .eml files — we import and parse them safely. And if the AI or network fails, the app never crashes; it retries and shows a clear message. Storage is local, so no one sees another user's data."
DemoChoose 2 → pick a .eml from the saved folder list → show the assessment. Then Ctrl+C for a clean exit (or briefly show 4 = view saved reports).
ActionMention CI runs tests + Docker on every push and the app is 100% procedural (a CI guard enforces it).
NoteUse a pre-tested plain-text .eml. If showing the offline message, toggle wifi only if rehearsed — otherwise skip it.
