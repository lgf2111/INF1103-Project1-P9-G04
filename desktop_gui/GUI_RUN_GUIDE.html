PhishReport · Docker GUI

Run the desktop GUI

Choose a native host window for the closest desktop feel, or use the browser-based fallback if you don't want to install an X server.

Before you start Native window Browser fallback Troubleshooting
What this demo includes: The GUI opens in Docker and uses a local, fixed demo authentication service. You can try sign-in, registration/reset UI, the empty Overview, account menu, locked Settings, and sign-out. Message assessment and report-history screens are not part of this desktop GUI yet.

Before you start

  1. Install and start Docker Desktop.
  2. Get the latest project files that include run.sh.
  3. Open a terminal at the project folder. On Windows, use Git Bash or WSL for the commands below.
  4. No Groq API key or host Python installation is needed for the GUI demo.

The first launch builds the GUI Docker image and can take several minutes. Later launches reuse the image unless the source or Docker dependencies change.

Option A: native X11 window

The app itself remains inside Docker; its window is drawn by an X server running on your computer. This is a desktop window, not a browser tab.

macOS: XQuartz

  1. Install XQuartz, then open it from Applications or Spotlight.
  2. Open XQuartz → Settings (or Preferences) → Security. Enable Authenticate connections and Allow connections from network clients.
  3. Quit XQuartz completely and reopen it so the settings take effect.

The launcher securely passes the current XQuartz authorization cookie to the GUI container using a temporary, read-only file and removes that file when the app exits. Do not use xhost +.

Windows: VcXsrv

  1. Install VcXsrv and start XLaunch with display 0.
  2. Allow VcXsrv through Windows Firewall only on a trusted Private network.
  3. If VcXsrv access control blocks Docker Desktop, it may require the XLaunch Disable access control option. Use this only on a trusted network, close VcXsrv after use, and prefer the browser fallback if unsure.

Native display support depends on the host X server and its access-control configuration. The macOS launcher passes XQuartz's cookie automatically.

Launch

From the repository root:

bash run.sh gui

The app should open in a native window. When finished, close the GUI or press Ctrl+C in the terminal. The temporary demo-auth container and Docker network are cleaned up automatically.

Option B: browser-based fallback

Use this mode if you don't want to install/configure XQuartz or VcXsrv. The app still runs in Docker, but noVNC streams its virtual display to a local browser.

bash run.sh gui-web

Open the local address printed by the command. If needed, use:

http://localhost:6080/vnc.html?autoconnect=true&resize=scale

The service is bound to 127.0.0.1. Keep it local; do not expose the noVNC port to a public network. Press Ctrl+C in the terminal to stop it.

Demo sign-in

The local development API returns one fixed demo user. It doesn't create accounts, send email, or store real user data.

Emaildemo@phishreport.test
Passwordphishreport-demo

Do not reuse this demo service or credentials for real accounts or production.

Troubleshooting

Native macOS launch says “could not connect to display”
Confirm XQuartz is open and both Security options above are enabled. In macOS Terminal, check its listener with nc -vz 127.0.0.1 6000. Then check Docker can reach it: 
docker run --rm phishreport-gui-native python -c 'import socket; socket.create_connection(("host.docker.internal", 6000), 3); print("XQuartz reachable from Docker")'
If the first check fails, restart XQuartz after changing Security settings. If only the Docker check fails, check macOS firewall settings and Docker Desktop.
“Authorization required” appears
Enable Authenticate connections in XQuartz Security and restart XQuartz. The current launcher should transfer the authorization cookie automatically. Don't bypass authorization with xhost +.
Qt mentions xcb-cursor0
This may be a generic Qt platform-plugin hint. The GUI image includes libxcb-cursor0; first verify the host display and X11 authorization are reachable.
I just want to try the UI
Use bash run.sh gui-web. It avoids host X-server setup.
The Docker command or target is missing
Make sure you have the latest project version with run.sh, and that Docker Desktop is running. On Windows, run from Git Bash or WSL rather than PowerShell.
Security note: X11 display access can expose or control windows in the X server session. Keep XQuartz/VcXsrv limited to trusted clients and networks. The demo authentication API is for local UI testing only.
